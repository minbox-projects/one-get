# Agent Note: 桌面下载界面与引擎服务

Status: implemented

[English](2026-11-13-desktop-download-ui.md) | 中文

## Problem

OneGet 已经拥有经过验证的桌面外壳、无界面下载引擎和持久任务存储，但还没有可用的下载界面。日常用户无法添加 URL、观察进度、暂停或继续任务、查看分段、打开结果、删除记录或文件，也无法修改下载设置，只能依赖外部工具。缺失的决策包括：如何在引擎之上组织任务优先的界面，渲染层如何在没有事件风暴的情况下观察进度，每个任务的目标目录与删除语义应放在哪里，设置和已存任务如何在不丢数据的前提下迁移，以及双语文本、键盘访问和超大数据列表应如何实现。界面还必须让同一目标目录下的同名任务彼此独立，在不存储令牌的前提下暴露重定向后的目标，在探测缓慢时保持服务响应，并将引擎失败本地化，而不是显示原始后端文案。本记录扩展了 [OneGet 桌面外壳基线](2026-11-11-oneget-desktop-shell-baseline.md) 与 [下载引擎与持久任务存储](2026-11-12-download-engine-task-store.md)；这两份记录在它们负责的进程、平台和无界面引擎决策上仍然有效。

## Decision

主窗口是任务优先的。侧边栏包含全部、下载中、已完成、失败以及带计数的类型分类；工具栏包含新建、批量、全部暂停、全部继续、搜索和设置；中央是任务列表；可折叠的详情面板显示选中任务；状态栏报告活动任务和总速度。分类来自清理后的最终文件名扩展名，并按大小写不敏感方式匹配。排序、过滤和关键词搜索针对完整数据集而不是仅渲染窗口。React 代码拆分为 `src/features/downloads/` 的下载界面、`src/features/settings/` 的设置界面和 `src/i18n/` 的词典，类型化包装器位于 `src/lib/downloads.ts`；组件不直接调用 Tauri。

列表使用带预取的固定高度虚拟列表，因此 10,000 个任务只挂载有界窗口内的行，同时第一行、中间行和最后一行仍可到达。默认排序为创建时间降序，状态排序使用固定顺序 downloading、connecting、finalizing、paused、queued、failed、completed、cancelled，并以创建时间作为并列时的次序。每个用户可见字符串都来自简体中文或英文词典，默认跟随操作系统语言，可立即切换，并使用与语言区域一致的数字、大小、速度、预计剩余时间和日期格式。对话框会捕获并恢复焦点，破坏性操作需要确认，只有图标的操作带有无障碍名称。

渲染层通过有界轮询观察进度。`downloads_list` 返回轻量摘要，在窗口可见时最多每秒运行一次，在窗口隐藏时停止，并在控制操作或变更后立即刷新。后端在一条专用线程和当前线程 Tokio 运行时上拥有引擎与存储；请求通过通道到达，运行循环被并发轮询，缓慢的探测与两个循环并行执行，因此列表和控制请求不会被阻塞。服务启动前完成启动恢复，暂停任务重新校验被限制为每个引擎实例只运行一次，而不是在每次运行循环重启时运行，关闭时暂停活动下载并拒绝后续工作。这样无需为每个任务建立事件流，也不会让渲染层状态无界增长，同时保持任务控制响应迅速。

每个任务保存其解析后的目标目录，并在已知后保存重定向后的目标。创建时校验该目录并随任务持久化，部件文件、最终文件、恢复、继续、打开文件夹和删除都复用该目录。最终 URL 与任务 URL 经过同一最小化处理，因此用户信息、查询和片段不会进入存储，`downloads_list` 以 `finalUrl` 暴露它，供详情行展示脱敏值。已存任务没有目标目录时回退到配置的默认目录；目录缺失、不是目录、不可读或不可写时返回 `INVALID_DESTINATION`，而不会在别处创建或继续文件。任务存储使用 schema 版本 2，在现有任务行上增加目标目录、完成时间和可空最终 URL，同时版本 1 迁移保持已有行可用。

部件命名会识别冲突。任务通常在其目标目录旁使用 `<sanitized filename>.oneget.part`。只有当同一目标目录中的另一个任务已经拥有或可能创建该名称时，引擎才使用 `<sanitized filename>.<first 8 of task id>.oneget.part`。所选名称持久化到 `part_path`，并作为下载、继续、完成、取消、恢复、删除和存在性检查的唯一部件标识；较旧的行回退到旧名称。最终文件唯一重命名行为保持不变。

设置使用 schema 版本 2，包含主题、日志级别、语言、关闭行为、可选默认目录、默认连接数、最大并发任务数和可选全局限速。版本 1 文档会在内存中迁移，同时保留主题、日志级别和未知顶层字段；损坏输入备份为 `.corrupt` 同级文件，未来版本的 schema 保持只读。语言和主题立即生效，默认值应用于新下载，并发数和全局限速保持引擎在任务开始时捕获的语义，界面会明确说明这一点。

删除和打开具有各自的安全规则。删除记录仅允许已完成、失败或已取消的任务；它会移除任务已记录的部件文件（若存在），并保留任何已完成的最终文件。删除文件仅允许已完成任务，需要二次确认，通过能力根校验最终文件后再移除该文件及其记录；最终文件缺失时返回 `FILE_MISSING` 并保留记录。打开文件要求任务已完成且最终文件存在，打开文件夹使用记录的目录；两者都经过无 shell 的平台打开器。

新建和批量对话框使用本地化的 `@tauri-apps/plugin-dialog` 目录选择器，无效目标目录会渲染为针对目标目录的可操作错误。稳定的引擎错误码在 `src/features/downloads/errorMessages.ts` 中映射到词典键；`CHECKSUM_MISMATCH` 告知用户仅在使用正确的预期 SHA-256 或不使用校验和时重试，成功操作显示本地化提示，分段区间按半开区间渲染，连接数和限速输入分别执行 1 到 64 的连接数与 `u64` 限速边界。任务优先外壳重写后，诊断面板仍是一个保留且经过测试但外壳不挂载的模块，而 Toast 原语已挂载。

浏览器层针对 `e2e/support/mock-ipc.ts` 中的确定性模拟 IPC 运行，不使用公共网络。它覆盖新建下载、暂停与继续、取消、记录与文件删除、设置持久化、语言切换和 10,000 行滚动。Rust 集成测试在保留的引擎套件之外覆盖命令面、设置迁移、存储迁移与目标目录、最小化最终 URL 持久化、同名任务部件隔离、删除以及打开器。本记录取代这些记录中较早的仅外壳界面表述，以及引擎记录中较早的单一部件名称和 schema 版本表述，同时保留它们在进程、平台、引擎和存储方面的不变量；两份记录仍然有效。

## Alternatives considered

- 为每个任务推送进度事件被否决，因为高任务数和快速更新会造成事件风暴和渲染层状态无界增长；对轻量摘要进行有界轮询保持了契约与界面的响应性。
- 只在设置中保存目标目录被否决，因为两个任务可以合理地指向不同文件夹，重启后继续也不能悄悄把部件文件移动到当前默认目录。
- 使用存储的路径字符串直接删除文件而跳过能力校验被否决，因为过期、被编辑或含链接的路径可能逃出目标根目录或删除无关文件。
- 只提升 schema 版本而不在内存中迁移版本 1 文档被否决，因为现有文档会丢失主题、日志级别或未知字段。
- 建立第二个任务存储或内存任务缓存被否决，因为恢复、跨实例控制和进度已经依赖单一持久存储；界面通过服务复用它。
- 在没有词典层的情况下构建界面被否决，因为双语文本、系统语言检测、即时切换和审计否则会逐组件返工。
- 为所有部件文件始终附加任务 ID 后缀被否决，因为这会改变常见单任务场景的既有名称并增加旧数据恢复的复杂度；只在真正冲突时附加后缀既保留简单名称，又让同名任务安全。
- 在服务循环中直接执行探测被否决，因为缓慢的网络探测会阻塞列表和控制请求；让探测与运行循环并行执行可保持响应性。
- 将操作系统文件打开器纳入受保护的子进程机制被否决，因为处理器必须比打开请求存活更久；进程组或 Job Object 会在打开器返回时将其杀死。

## Consequences

后续界面工作必须使用这里记录的功能边界、类型化包装器、词典、虚拟列表、轮询契约和原生目录选择器。后续引擎工作必须保持每个任务的目标目录、冲突感知的部件名称、仅限终态的记录删除、仅限已完成任务的文件删除、最小化最终 URL 以及无 shell 打开器不变。设置和任务存储的 schema 变更必须保留版本 1 迁移和未知字段保留行为。受保护的子进程保留整树终止规则，分离的操作系统处理器仍是刻意的例外。

- 迁移、部件命名、本地化和删除规则仍要求保留的引擎、存储、设置、命令和打开器测试套件保持通过。
- macOS 与 Windows 手动验收、真实应用本地下载、长时间压测和设计评审仍是必需的外部证据；自动化与模拟 IPC 结果不能替代它们。
- 上下文索引器只发现 TypeScript 模块，因此 Rust 引擎、存储、命令和工具导航条目仍由手工维护。
