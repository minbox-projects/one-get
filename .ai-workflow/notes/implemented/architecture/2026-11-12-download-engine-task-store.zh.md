# Agent Note: 下载引擎与持久任务存储

Status: implemented

[English](2026-11-12-download-engine-task-store.md) | 中文

## Problem

OneGet 在构建任何桌面下载界面之前，需要一套无界面的下载引擎和持久任务存储。该引擎必须安全探测远程文件、规划有界分段、在进程崩溃后继续，并以原子方式完成文件，同时不暴露查询令牌、Cookie、代理凭据或自定义请求头的值。若没有记录在案的决策，后续工作可能把部件文件当作可选项、从存储中重放秘密请求头的值、盲信探测得到的 Range 声明，或直接写出最终文件并留下不完整输出。

## Decision

交付的引擎是 `src-tauri/src/engine/` 下的 Rust 库，配合 `src-tauri/src/store/` 下的 SQLite 存储和 `src-tauri/src/bin/engine_harness.rs` 中的命令行工具。它扩展而非取代 [OneGet 桌面外壳基线](2026-11-11-oneget-desktop-shell-baseline.md)：外壳负责进程、平台、日志、设置和能力边界，引擎对每一次受管文件操作都调用平台 `CapDir`。

部件文件是字节事实，SQLite 分段行是进度事实。每个任务在目标文件旁拥有一个 `<sanitized filename>.oneget.part`，以绝对 `u64` 偏移写入，并通过 `CapDir` 预分配已知总长度。存储使用 schema 版本 1，包含 `tasks`、`segments` 和 `schema_meta`，启用 WAL、外键、五秒忙等待，在 Unix 上把数据库设为 `0600`，迁移前备份，并拒绝更新版本的 schema。分段行使用半开区间，保持不重叠且无空洞，连接数为 1 到 64，除小文件或最后余量外最小为 1 MiB。

调度器按 FIFO 领取最旧的排队任务，只有 connecting、downloading 和 finalizing 状态计入并发上限。暂停、继续、取消、重试和启动恢复在各自定义的状态内都是幂等的。继续会重新探测远程元数据，并以 `FILE_CHANGED` 拒绝已变化的 ETag、Last-Modified 或总长度；部件缺失则以 `PART_MISSING` 失败。恢复会重新排队仍有部件的中断任务、重新完成处于 finalizing 的任务、只删除已取消任务自己的部件，并保留暂停和失败任务的部件。

完成阶段停止工作线程、同步部件、流式计算 SHA-256、在重命名前持久化哈希、校验任何期望哈希、在冲突时选择唯一名称，并通过能力层执行替换。探测结果只是建议：引擎在启动完整工作池前重新校验第一个区间，新任务收到 `200` 时回退为单连接，已有字节后收到 `200` 则以 `RANGE_IGNORED` 失败，绝不在非零偏移写入完整响应体。

重试最多五次，使用指数退避和完全抖动；整数秒 `Retry-After` 会被精确遵守，HTTP-date 值则使用回退延迟。限速是每个任务共享、并可选全局共享的字节漏桶。HTTP 代理拒绝内嵌 userinfo，并把可选的基础认证保留在内存；Netscape Cookie 按主机、路径、过期时间和 secure 标记限定范围，并在每次任务开始时重新加载；安全的自定义请求头被接受，而被禁止或含 CRLF 的请求头被拒绝。

隐私与崩溃行为一并记录。请求头的值、Cookie 值、代理凭据、授权值和 URL 查询或片段令牌绝不进入存储或日志。安全的请求头名称可以带空值保存，存储的 URL 会剥离 userinfo、查询和片段，日志只携带事件名、标识符、字节数和错误码。macOS 使用稀疏 `set_len`；Windows 尝试 `FSCTL_SET_SPARSE` 并报告显式回退。短冒烟测试随普通测试套件运行，被忽略的长时间压测则针对本地夹具重复整个生命周期。

## Alternatives considered

- 只把进度保存在部件文件元数据和旁路日志中被否决，因为多分段进度和队列状态需要存储提供的原子快照和查询能力。
- 为精确重放而持久化完整请求头值被否决，因为存储中的隐私泄露是永久性的；值只保留在内存中，后续会话必须重新提供。
- 持久化带查询的 URL 或签名令牌因同样原因被否决；只有最小化后的 URL 会被持久化。
- 依据探测结果直接启动完整工作池被否决，因为服务器可能声明支持 Range 却在之后返回 `200`；首个区间复验和工作线程级防护因此保留。
- 直接写入最终名称被否决，因为崩溃或校验失败会留下不完整最终文件；部件文件加能力层替换保证最终名称的原子性。
- 在 Windows 上完整分配逻辑长度被否决，因为这会为稀疏区间消耗磁盘；稀疏尝试保留了显式回退结果。

## Consequences

后续桌面工作必须调用这套引擎和存储，而不是重复实现下载或持久化逻辑。任何添加任务的界面都必须传入可在重启后重新提供的值，因为请求头的值和带查询的 URL 无法从存储重放。存储仍是进度权威，部件文件仍是字节权威；已完成任务始终拥有最终文件和匹配的已存哈希。

该设计接受一个已知限制：新进程无法从数据库重建秘密请求头的值或签名 URL，因此重启后的继续依赖调用方重新提供它们。引擎也不会发起系统代理发现、SOCKS5、浏览器 Cookie 提取、HuggingFace 请求、遥测或远程上报尝试。

- 平台相关的分配与替换留在 `src-tauri/src/platform/`；引擎在该边界之外不按目标操作系统分支。
- 新的网络设置属于后续变更，通过现有引擎方法提供新增的代理、Cookie、限速或请求头输入。
- 在下载能力可被视为完全验收之前，24 小时压测和 Windows x64 运行仍是必需证据。
