# Project memory

This file records the current standards and behavior of the OneGet desktop downloader, its task-first React interface, its download engine, its durable task store, and its loopback browser-capture boundary. Agent Notes record why decisions were made; keep both consistent in the same change.

- `src-tauri/src/commands/` is the Tauri command surface plus directly testable download, settings, diagnostics, pairing, and quit service functions.
- `src-tauri/src/api/` owns the loopback HTTP service, fixed admission guards, capture protocol and validation, dedicated pairing database, bounded rate limiters, duplicate suppression, and the desktop bridge for takeover and prefill.
- `src-tauri/src/engine/` owns the headless probe, safe HTTP transport, planner, part file, worker pool, scheduler, long-lived service actor, retry, rate limiting, cookies, per-task destinations, deletion, state machines, and typed engine errors.
- `src-tauri/src/store/` owns the SQLite connection, schema version 1 and 2 migrations, per-task destinations, part names, minimized final URLs, task and segment records, and progress persistence.
- `extension/shared/` is the browser-agnostic extension runtime: background controller for pairing, observation, takeover, prefill, resource bounds, and failure state; typed browser adapter for callback and promise APIs; isolated content script, MAIN-world request observer, and overlay styles; plus protocol client, classification, HLS and DASH recognition, segment filtering, page ownership, bounded resource store, settings validation, bilingual strings, and filename display.

- `src-tauri/src/bin/engine_harness.rs` is the command-line harness (`run`, `status`, `pause`, `resume`, `cancel`) for local fixture checks and crash recovery.
- `src-tauri/tests/support/` holds the deterministic local range, proxy, cookie, fault, and fixture helpers; `scripts/soak-test.sh` wraps the ignored long soak.
- `src-tauri/src/platform/` owns all target-specific behavior: paths, filenames, capability files, shell-free opener, processes, secrets, deep links, tray, autostart, and notifications.
- `src-tauri/src/kernel/` owns canonical JSON and Ed25519 manifest verification only.
- `src-tauri/src/config.rs`, `logging/`, and `error.rs` own settings, JSON-line logs, and typed errors.
- `src-tauri/tests/` holds the Rust integration suites for download commands, settings, store, opener, shell, engine, soak, the loopback API, and pairing commands; `extension/tests/` holds shared and controller unit tests plus the extension Playwright harness; `e2e/` holds Playwright checks backed by deterministic mock IPC in `e2e/support/mock-ipc.ts`; `scripts/` holds the pin check, the soak wrapper, and local macOS signing helpers.
- `localdocs/` is ignored local reference material, not shipped product documentation.

## Platform-layer rule

Target-specific branches belong only in `src-tauri/src/platform/**` and platform-specific Tauri configuration. Shared modules call platform interfaces and never branch on the target operating system. New platform behavior needs an interface in the platform layer plus a test in the corresponding suite.

## Download engine and task store

- Entry points: `Engine` in `src-tauri/src/engine/scheduler.rs` (`new`, `add_task`, `run`, `pause`, `resume`, `cancel`, `retry`, `recover`, `delete_record`, `delete_file`, `open_file`, `open_folder`, `set_max_concurrent`, `set_proxy`, `set_cookie_file`, `set_task_rate_limit`, `set_global_rate_limit`, `set_logger`), `EngineService` in `src-tauri/src/engine/service.rs`, `Database` in `src-tauri/src/store/db.rs`, and `DownloadSpec` in `src-tauri/src/engine/worker.rs`.
- Engine service: one dedicated thread with a current-thread Tokio runtime owns the engine and store. Requests arrive through a channel and the run loop is polled concurrently with them; slow probes run alongside both loops so a pending probe does not stall task listings or controls. Startup recovery completes before `start` returns; paused-task revalidation is guarded to run once per engine instance rather than on every run-loop restart; and `shutdown` pauses active downloads and refuses later work. `settings_save` applies the maximum concurrent tasks and global rate limit to the live engine.
- Task filenames and destinations: `Engine::add_task` runs the platform-aware sanitizer for the current target before the name reaches the store or the in-memory spec. The sanitizer never returns an empty or dot-segment name, so task creation cannot persist a traversal or separator component. The resolved destination is validated, stored with the task, and reused for the part and final file after restart; a stored task without a destination falls back to the configured default, and an invalid destination fails with a typed `INVALID_DESTINATION` error. The post-redirect URL is stored in the same minimized form as the task URL and exposed as `finalUrl` in list summaries and details.
- Deletion and opening: `delete_record` accepts only completed, failed, or cancelled tasks and removes only the task's own part while keeping a final file. `delete_file` accepts only completed tasks, removes the capability-validated final file and then the record, and returns `FILE_MISSING` while keeping the record when the final file is absent. `open_file` requires a completed task and an existing final file; `open_folder` uses the recorded destination; both use the shell-free platform opener.
- Part-file operations: the engine resolves the task's persisted `part_path` and falls back to the legacy `<sanitized filename>.oneget.part` name only when none was recorded. Part existence and removal go through `CapDir::exists` and `CapDir::remove_file`, which apply the same path validation, canonical-root check, and symbolic-link refusal as every other managed operation. A missing part is not an error on cancel, and a part that resolves outside the destination root is never touched.
- SQLite schema version 2: `schema_meta`, `tasks`, and `segments`; version 2 adds nullable `destination`, `completed_at_ms`, and `final_url` to `tasks`, and version-1 rows keep a null destination and final URL until they are resolved or recorded. WAL, `synchronous=NORMAL`, foreign keys, a five-second busy timeout, and `0600` on the database plus `-wal` and `-shm` on Unix. Back up a non-empty database before a migration, migrate in one transaction, verify indexes and constraints, and refuse a newer schema. Timestamps are epoch milliseconds; offsets are signed 64-bit columns whose non-negative range preserves `u64`.
- Task states: `queued`, `connecting`, `downloading`, `paused`, `finalizing`, `completed`, `failed`, `cancelled`. Segment states: `pending`, `active`, `done`, `failed`. Only the checked transitions persist; anything else returns `INVALID_STATE`. `completed` requires a final file and matching stored hash; `paused` and `failed` preserve the part; `cancelled` removes only its own part.
- Queue: FIFO claim of the oldest queued task. The concurrency limit counts only `connecting`, `downloading`, and `finalizing`; a paused task does not consume a slot; a limit change takes effect without a restart.
- Cross-engine coordination: more than one `Engine` may open the same database. A pause or cancel applied through one instance is reconciled from the reloaded stored row by the other, so a concurrent pause ends `paused` and a concurrent cancel ends `cancelled` instead of `failed` or `INVALID_STATE`. A cancel that wins during finalization removes the part and leaves no final file, and a finalizing replacement that loses to a cancel removes the file it created.
- Data truth: the chosen part file is the byte truth and SQLite segment rows are the progress truth. A task normally uses `<sanitized filename>.oneget.part` beside its destination; only when a same-filename task in the effective destination conflicts does the engine choose `<sanitized filename>.<first 8 of task id>.oneget.part`. Conflict detection compares the effective destination, so a version-1 row without a stored destination falls back to the engine default directory, and it includes any same-filename task that is not completed or cancelled plus terminal rows whose part file still exists. The part-name choice and task insert share one `BEGIN IMMEDIATE` transaction, so two engine instances cannot race for the same name. The chosen name is persisted in `part_path` and is the single part identity for download, resume, finalize, cancel, recovery, delete, and existence checks, with the legacy name as fallback. A known total is preallocated sparsely through `PartFile::preallocate` and `CapDir::preallocate_sparse`, an unknown total starts empty, and writes use absolute `u64` offsets. A preallocation failure on a full device maps to `DISK_FULL` and pauses the task; other preallocation failures fail it. Progress persists at least once per 128 KiB read chunk.
- Finalization: stop workers, sync the part, stream SHA-256, persist the computed hash before the rename, verify an expected hash case-insensitively, choose a unique `stem (n).ext` name on collision, replace through `CapDir` without overwriting or following links, and sync the parent directory. A checksum mismatch fails with `CHECKSUM_MISMATCH` and creates no final file. A cancel from another engine instance that lands during finalization stays authoritative: the part is removed and no final file is left behind.
- Recovery: interrupted `connecting` or `downloading` tasks requeue when the part exists and fail with `PART_MISSING` otherwise; `finalizing` tasks re-finalize idempotently; a final-only file must match its stored hash, or, without one, the recorded total plus any expected hash; a cancelled leftover part is removed; paused and failed parts stay.
- Probe and Range: one ranged `GET` with `Range: bytes=0-0` and `Accept-Encoding: identity`; classify 206, 200, 416, HTML, and HTTP errors without reading the body. HTTP/1.1 only, no automatic redirects, ten manual hops, 15-second connect and 30-second read timeouts, no compression, and no public-network dependency. A probe is independent of the run loop, so a slow probe never stalls downloads or list and control requests. Revalidate the first range before the pool; a 200 with no bytes written falls back to one connection, and a 200 after bytes exist fails with `RANGE_IGNORED` without writing.
- Planning and splitting: 1 to 64 connections, half-open gap-free segments, 1 MiB minimum except the whole file or final remainder, and one open-ended segment for unknown length or no Range. A segment may split at most twice, only with an idle worker, at least two minimum segments remaining, and a split point ahead of the current offset; persist the shortened range and its tail in one transaction.
- Retry and faults: at most five attempts with exponential backoff and full jitter between 50 milliseconds and two seconds. Integer-seconds `Retry-After` is honored exactly; an HTTP-date or malformed value uses the exponential fallback. Do not retry 401, 403, 404, HTML, checksum, or a Range-ignored failure after data. A short body resumes at the persisted offset, an overlong body is truncated at the segment end, an invalid Content-Range start is `RANGE_MISMATCH` without writing, and ENOSPC pauses with `DISK_FULL`.
- Rate limiting: a byte leaky bucket paces each streamed chunk. Per-task and optional global limits share the schedule across a task's workers; zero or absent is unlimited. Rate-limit inputs are capped at `Number.MAX_SAFE_INTEGER`, the largest value the IPC number boundary carries without rounding.
- Network boundaries: an HTTP proxy URL must not embed userinfo, and optional basic authentication stays in memory. Netscape cookies match host, include-subdomains, path, secure, and expiry; they are reloaded at task start or resume and recomputed per redirect hop. Reject `Host`, `Authorization`, `Cookie`, `Range`, `Proxy-Authorization`, `Content-Length`, `Connection`, `Transfer-Encoding`, `Upgrade`, `TE`, `Trailer`, and `Set-Cookie` custom headers, and reject CR or LF in names or values.
- Privacy: header values, cookie values, proxy credentials, authorization values, and URL query or fragment tokens are never persisted or logged. Safe header names may be stored with empty values; values stay in memory only. The stored task URL and post-redirect final URL strip userinfo, query, and fragment. Logs carry event names, task and segment identifiers, byte counts, and stable error codes only. No telemetry, remote reporting, SOCKS5, system-proxy discovery, browser-cookie extraction, or HuggingFace request is added.
- Platform: macOS uses sparse `set_len`; Windows attempts `FSCTL_SET_SPARSE` before extending and reports sparse or an explicit fallback. Both use the capability-scoped replace path.
- Harness and soak: `cargo run --bin engine_harness -- run|status|pause|resume|cancel` against a local fixture. The short smoke runs in `cargo test --test soak`; the ignored long run is `ONEGET_SOAK_SECONDS=86400 cargo test --test soak -- --ignored --nocapture` in `src-tauri/` or `bash scripts/soak-test.sh 86400`.

## Browser integration and capture protocol

- The loopback API binds `127.0.0.1:37652` synchronously before serving on a dedicated current-thread Tokio thread. It is optional: a bind or pairing-database failure leaves downloads and settings usable and reports browser integration unavailable with the stable reason code of the failure, including `PAIRING_UNAVAILABLE` when no pairing store is attached, `API_BIND_FAILED` when the port cannot be bound, and `PAIRING_SCHEMA_UNSUPPORTED` when the pairing schema is newer than this build. Shut the API down before the engine on quit.
- Routes are `GET /health`, `POST /pair`, `POST /capture`, and `POST /pair/revoke`. Admission order is the request-header budget, exact loopback `Host`, route origin, JSON content type for the two body routes, bearer authentication for capture and revoke, then the route rate limit and body validation. `/health` allows an absent `Origin`, rejects a present non-extension origin, and returns app version, protocol version 1, and capture, prefill, and takeover capabilities without authentication.
- Limits: 64 KiB body, 50 capture items, 8 KiB URL, 255 UTF-8 bytes for a filename, 10 safe capture headers with 128-byte names and 2048-byte values, 64 request headers and 16 KiB combined header bytes, 10 pairing requests per origin per minute, 120 capture requests per token per minute, and 256 retained keys per limiter. Rejections use typed `{ code, message }` bodies and create no task or prefill.
- Pairing codes are eight digits with a ten-minute lifetime, one active code at a time, superseded by a new code and discarded when the app reopens. A token is 256 random bits as 64 lowercase hexadecimal characters and is returned exactly once. `pairing.db` stores only SHA-256 hashes of codes and tokens plus the exact browser-extension origin (Chromium `chrome-extension://` or Firefox `moz-extension://`), label, and timestamps, with schema version 1, WAL, `synchronous=NORMAL`, a five-second busy timeout, and `0600` on Unix. Five failed codes lock pairing for five minutes; authorization requires the exact bound origin; last-used updates are throttled to once per minute; revocation deletes the client.
- Capture intents are `takeover` and `prefill`. A takeover carries exactly one item, creates one task, and returns the existing task with `duplicate: true` for a repeated token-bound `sourceId`. A prefill carries one or more items, stores one in-memory pending list, emits `app://capture-prefill`, and creates no task. Only the safe headers `Referer`, `User-Agent`, `Accept`, and `Accept-Language` are accepted; cookies, authorization values, arbitrary headers, credentialed URLs, and kinds other than `file` are rejected.
- Prefill delivery uses the event plus a fetch-on-open command. One item opens New Download with URL, filename, and a `Referer` header; multiple items open Batch Download with their URLs. A busy dialog defers the prefill until it closes, a second prefill replaces the pending one, dismissing the dialog drops it, and no prefill survives an app restart.
- Both extension packages are MV3 with `webRequest`, `downloads`, `storage`, `tabs`, and `webNavigation`, host permissions for HTTP(S) pages and loopback, and `script-src 'self'`. Chromium runs a service worker and retains `downloads.onDeterminingFilename`; Firefox runs a `background.scripts` event page with Gecko ID `oneget@oneget.app`, `strict_min_version` 140.0, and `data_collection_permissions.required: ["none"]`, and has no `onDeterminingFilename`. The isolated content script owns the overlay and forwards metadata; a MAIN-world script observes fetch, XHR, media elements, and SPA navigation without extension APIs. The token and settings live in the browser's local storage area; bounded resource metadata lives only in the session storage area.
- Resource categories are `video`, `audio`, `archive`, `program`, `document`, `model`, and `other`, derived from the lowercased filename extension first and MIME type second. HLS is `.m3u8` or an HLS manifest MIME; DASH is `.mpd` or `application/dash+xml`. Manifests are listed but never takeover candidates and are never fetched for parsing. `.ts`, `.m4s`, `.m4f`, `.cmfv`, `.cmfa`, `init.mp4`, and `videoplayback` range, sequence, or fragment URLs are filtered.
- Takeover reads the current token and settings per decision, checks enablement, category, blacklist host and subdomain, incognito, extension-originated, non-HTTP, manifest, unsupported kind, and known size, and exempts unknown sizes from the minimum-size rule. Chromium decides in `downloads.onDeterminingFilename` and still calls `suggest()`; Firefox decides in `downloads.onCreated`, reduces an absolute filename to a sanitized basename with a URL-derived fallback, treats `totalBytes: -1` as unknown, and can miss a download that finishes before cancellation. It sends the capture before canceling and erasing the browser download; a failed capture leaves the download intact and records `takeoverError { downloadId, url, filename, reason }` for `popup/get-state`, where the popup shows a localized banner with a Send to OneGet prefill retry. Chromium keeps that record in memory; Firefox keeps the same bounded record in session storage so an event-page suspension does not lose the retry path. Reasons are `token_revoked` after a 401 clears the token, `update_required` after a 409, and `capture_failed` otherwise; it is never written to persistent storage and clears after a successful takeover or same-URL prefill retry. The per-tab store keeps at most 500 entries per tab and 50 tabs, clears the sending frame on a frame navigation or a subframe SPA route change, the whole tab on a top-frame tab navigation or SPA route change, and the tab on close.



## Command and event contract

- Commands: `app_info`, `settings_get`, `settings_status`, `settings_save`, `deep_link_last`, `diagnostics_secret_roundtrip`, `diagnostics_notification_status`, `diagnostics_send_notification`, `diagnostics_autostart_get`, `diagnostics_autostart_set`, `app_graceful_quit`, `downloads_list`, `downloads_segments`, `downloads_probe`, `downloads_add`, `downloads_pause`, `downloads_resume`, `downloads_cancel`, `downloads_retry`, `downloads_delete_record`, `downloads_delete_file`, `downloads_open_file`, `downloads_open_folder`, `pairing_status`, `pairing_generate_code`, `pairing_list_clients`, `pairing_revoke`, and `pairing_take_pending_prefill`.
- `settings_status` reports whether the loaded document is read-only because of a future schema and whether corrupt input was recovered; it never returns the document content.
- Events: `app://deep-link` with `{ accepted, url?, error? }` and `app://capture-prefill` with `{ items, receivedAtMs }`.
- Pairing commands never return a bearer token: status and client views carry only identifiers, origins, labels, and timestamps. `pairing_take_pending_prefill` takes the one pending prefill exactly once.
- `downloads_list` summaries and task details expose the minimized post-redirect target as `finalUrl`.
- Rust payloads use camelCase and typed `{ code, message }` errors. A missing engine reports `engine_unavailable`.
- The frontend calls only `src/lib/tauri.ts` or the typed wrappers in `src/lib/downloads.ts` and `src/lib/pairing.ts`; components never invoke Tauri directly. A missing Tauri runtime yields `runtime_unavailable`; the shell must not crash in a browser preview.
- Blocking keyring, file, settings, and download work runs through `spawn_blocking` or the engine service thread; no command blocks the UI thread.
- Polling: the UI calls `downloads_list` at most once per second while the window is visible, pauses while it is hidden, and refreshes after a control action or mutation. Do not add a per-task progress event stream.
- Quitting: `app_graceful_quit`, the close behavior, and the tray path shut the engine service down before exit; do not start a second engine over the same task database.

## Desktop interface

- The main window is task-first: sidebar state and type filters with counts, a toolbar with New, Batch, Pause All, Resume All, search, and Settings, a central task list, a collapsible details panel, and a status bar with active-task and total-speed information. The empty state explains how to add a download. `src/features/diagnostics/DiagnosticsPanel.tsx` remains a retained, tested module, but the task-first shell does not mount it. The `Toast` primitive is mounted for localized success feedback.
- The task list virtualizes fixed-height rows with overscan so at most a bounded window of rows is mounted, while sorting, filtering, and search operate on the full data set. The default sort is creation time descending; the state sort uses the fixed order downloading, connecting, finalizing, paused, queued, failed, completed, cancelled with creation time as the tiebreaker.
- Every user-visible string comes from `src/i18n/` in Simplified Chinese or English, follows the operating-system language by default, switches immediately, and persists in settings. Numbers, sizes, speeds, ETA, and dates use locale-aware formatting; components must not hardcode user-facing prose. Stable engine error codes map to dictionary keys through `src/features/downloads/errorMessages.ts`; `CHECKSUM_MISMATCH` tells the user to retry only with the correct expected SHA-256 or without it, and success actions show localized toasts.
- Dialogs trap and restore focus, icon-only actions have accessible names, destructive actions require confirmation, and a keyboard-only user can complete new download, control, details, settings, and record-deletion flows. The task list exposes list and row semantics.
- New and batch dialogs use the localized `@tauri-apps/plugin-dialog` 2.8.4 directory picker. Connection input is a whole number from 1 to 64 within the `u32` range, rate input is a positive whole number at most `Number.MAX_SAFE_INTEGER`, the largest value the IPC number boundary carries without rounding, and an invalid destination surfaces as a destination-specific actionable `INVALID_DESTINATION` error. Segment ranges are half-open, with the end offset exclusive.
- Loading, empty, filtered-empty, retryable error, confirmation, and success states are explicit. A missing runtime or rejected IPC renders a localized non-crashing state with retry guidance and no secret values.
- `e2e/support/mock-ipc.ts` provides deterministic IPC for browser checks; Playwright flows must not depend on a public network or a real credential.

## Security invariants

- No analytics, telemetry, remote script sources, or remote connect sources. The production CSP is bundled-only except IPC; keep the no-telemetry rule when adding any network behavior.
- Deep links accept only `oneget://download` with exactly one `url` parameter, an `http` or `https` target, no embedded credentials, valid percent encoding, and at most 8 KiB.
- Credential values live only in the operating-system credential store. Never write them to settings, logs, diagnostics payloads, or frontend state; diagnostics return booleans only. Values are redacted in formatting and zeroized on drop.
- Managed file access goes through `CapDir` under a canonical root. Reject absolute paths, parent or current components, NUL bytes, and symbolic-link or junction escapes; atomic replace refuses link sources and destinations.
- Sanitize user-supplied filenames with the platform-aware sanitizer before use.
- Manifest verification uses canonical JSON with sorted keys and no whitespace, rejects duplicate keys and input above 1 MiB, removes the top-level signature before hashing, and uses `verify_strict`. The verifier does not install, download, or execute components.
- Guarded child processes never use a shell; they run in a Unix process group or Windows Job Object with whole-tree kill and timeout. The shell-free platform opener is the intentional exception: it launches the operating-system handler detached and fire-and-forget with no process guard, because a guard would kill the handler the application must leave running.
- The main window hides on close by default and can be configured to quit instead; the tray provides Show and Quit; graceful quit shuts down the engine, records a shutdown event, and exits with code 0.
- The engine store is the progress authority and the part file is the byte authority. Never write a full `200` body at a nonzero offset, never produce a partially written final file, and never mark a task completed without a matching stored hash.
- Record deletion never removes a completed final file, and file deletion is allowed only for a completed task after a second confirmation; the engine validates the final file through the capability root before removing it and its record.
- The platform opener runs without a shell, launches the operating-system handler detached without a process group or Job Object, and refuses to launch a path that does not exist or a non-completed task.
- The engine rejects non-HTTP schemes, credentialed targets, HTTPS-to-HTTP redirects, URLs over 8 KiB, forbidden headers, and CRLF-bearing header values before a request.
- Cookie values, proxy credentials, authorization values, URL query tokens, and custom header values never enter the SQLite store or the structured log. The store keeps only necessary recovery fields.
- The local API binds only `127.0.0.1`, requires the exact loopback `Host` on every route and the exact paired browser-extension origin on every write — `chrome-extension://` with 32 `a`–`p` characters or `moz-extension://` with a lowercase 8-4-4-4-12 UUID — reads bearer tokens only from the `Authorization` header, and returns no wildcard CORS. The accepted scheme changes no admission order, limit, token binding, or error code, and it enforces body, item, URL, header, protocol, and rate limits before creating a task or prefill.
- `pairing.db` stores only SHA-256 hashes of single-use codes and bearer tokens plus the exact bound browser-extension origin, label, and timestamps. Never return a token from a desktop command, log it, write it to settings, or render it in the UI.
- Capture accepts only URL, filename, referer, MIME type, size, file kind, and the four safe headers. Reject cookies, authorization values, arbitrary headers, credentialed URLs, and unsupported kinds before the engine or dialog sees them; prefill content stays in memory and is never persisted.
- Both extension packages use bundled-only MV3 scripts with no remote code or eval, no cookies or native messaging, and no telemetry; the Firefox package also declares no data collection. The MAIN-world observer never reads response bodies or credentials, and resource metadata stays session-only and bounded.
- Takeover posts the capture before canceling or erasing the browser download, creates at most one task per token-bound source, and leaves the browser download intact on failure. The failure surface is memory-only on Chromium and session-storage bounded on Firefox so an event-page suspension keeps the localized popup retry, and it is never written to persistent storage.

## Settings, logging, and errors

- Settings use `schemaVersion: 2` with `theme` (`system`, `light`, `dark`), `logLevel` (`error`, `warn`, `info`, `debug`, `trace`), `language` (`system`, `zh-CN`, `en-US`), `closeBehavior` (`tray`, `quit`), optional `defaultDirectory`, `defaultConnections` (8), `maxConcurrentTasks` (3), and optional `globalRateLimit` in bytes per second. A version-1 document migrates in memory without losing theme, log level, or unknown fields. Preserve unknown top-level fields, save atomically through a same-directory temporary file and rename, back up corrupt documents to a `.corrupt` sibling, and treat a future schema as read-only. Language and theme apply immediately; default directory and connections apply to new downloads; concurrency and the global rate limit apply to new tasks after saving while running downloads keep their captured limits, and the UI states this; close behavior applies immediately.
- Logs are JSON lines with `timestamp`, `level`, `event`, and redacted `fields`. Redact credential-bearing URL parts, authorization and cookie headers, URL userinfo, proxy credential fields, and provider credential prefixes before serialization.
- Rotation defaults to 10 MiB per file and five files including the current file; a record is never split across files. Debug builds also write the redacted line to stderr.
- Errors are user-safe typed `AppError` values with stable codes and no internal paths, stack traces, or credential values. `EngineError` follows the same rule and carries an internal retryability flag and optional retry delay.
- The task database is not a settings store. It holds minimized task URLs, filenames, per-task destinations, states, offsets, remote metadata, hashes, error codes, connection counts, timestamps, and safe header names with empty values.
- The pairing database is a separate `pairing.db`, not part of the task store. Deleting it revokes every paired client and affects no task, completed file, or setting. The settings schema stays version 2 and the task-store schema stays version 2.
